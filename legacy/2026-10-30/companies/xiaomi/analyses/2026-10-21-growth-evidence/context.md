# 研究规则

## 证据和口径

1. 优先公司原始公告、交易所文件、监管数据；行业研究采用有方法说明和明确日期的机构原文。
2. 每项关键数字注明原始链接、数据期间、单位、币种、范围，以及披露、复核或推断状态。
3. 出货量、销量、交付量、订单不可混用；营收、毛利、经营利润、调整后净利润、自由现金流分别判断。
4. 季度不能机械年化；上市公司指引、机构预测、自己的情景分开。
5. 记录价格的交易所、币种和采样时间；过期价格不得称为当前价格。收益率计算包含汇率、分红与摊薄的假设。

## 判断纪律

- 每个核心结论列出支持证据、相反证据、关键假设及失效条件。
- 先辨认竞争地位、资本回报和资金需求，再讨论估值。
- 公司成长、每股盈利成长和股东回报分别推导。优秀企业也可能因买价过高带来低回报。
- 不把多业务简单相加当作协同；观察获客成本、交叉购买、留存和资本占用的实际变化。
- 数据未复核时允许形成工作假说，必须保留状态，禁止升级成确定事实。

## 版本、验证与复盘

公司共享资料持续更新；每次分析独立保存，context.md 固化当时采用的公共上下文。已留档正文不覆盖；追加验证、纠错说明或新建研究。

复盘同时包含成功与失败，不用后来信息美化当时可得信息。把公司专用改进写回 shared/learnings.md，把跨公司改进写入 lessons.md，并说明适用边界。

本工具不执行买卖。行情更新由 tools/pipeline.py refresh 显式执行，写入当前CSV与原始响应档案；Web仅读取已保存文件。历史研究固定输入，不随行情刷新。计划、财报、行业资料与事件保存合同见 data-contract.md。

# 分析方法论

## 方法复用与资料入口

依次使用通用规则、[行业方法](playbooks/smartphones.md)、公司shared差异说明、单次分析快照。汽车参见[汽车方法](playbooks/automotive.md)，互联网与AI参见[平台方法](playbooks/platforms.md)。资料的原件、计划、事实、行情和事件按[数据合同](data-contract.md)保存。每条核心判断用claims.csv引用facts.csv，参数和结果进入runs/；行业方法持续更新但历史context不改写。

## 一、明确问题与时间边界

写出这次研究试图回答的单一问题、决策期限、信息截至日和无法获取的资料。先写可能推翻结论的证据，防止只检索支持材料。

## 二、理解收入与利润来源

按业务拆解收入 = 数量 × 单价；利润 = 收入 × 毛利率 − 费用。对平台业务另拆用户、时长、商业化率和监管约束；对制造业务另拆产能、渠道库存、折旧、营运资金与资本开支。

检查会计利润能否转为现金：经营现金流 − 维持竞争力所需的资本开支；明确现金流定义与公司口径差异。增长并非都创造价值，比较新增资本回报与资本成本。

## 三、竞争与海外

逐项比较目标客户、产品价格、性能、渠道、生态、成本与本地政策。市场份额必须采用同地区、同期间、同定义数据。海外收入增长拆为市场需求、份额、汇率、本地化产能和渠道变化；把关税、合规、售后与汇回风险纳入利润测算。

## 四、成长来源

按业务区分行业增量、份额提升、价格或结构改善和新业务。计算各项对收入、利润与现金流的增量贡献。验证高基数、低基数和收购影响。

## 五、估值与情景

使用保守、基准、积极三种情景，明确数量、单价、利润率、资本开支、股本和汇率。公司指引不等于一定实现，自己的假设不应伪装成一致预期。

- 复合增速 = (终值 / 初值)^(1 / 年数) − 1。
- 每股盈利 = 归属股东利润 / 稀释后股数；回购和股权激励都要计算。
- 企业价值法：企业价值减净债务及少数股东权益，再加独立估值的非经营资产；现金是否重复计入要核对。
- 分部估值适用于结构清晰的多业务公司；分部利润、集团费用和内部交易口径应一致。
- 现金流折现明确折现率和终值；终值占比过高时下调结论信心。

用敏感性检验找出决定结果的两个变量，再估计当前价格已经隐含何种增长。不能只说“估值比历史低”。

## 六、验证计划与复盘

每个重要假设对应一项待验证事项：指标、来源、观察日期、支持阈值、反证阈值、负责人或未认领。新公告出现后追加观察。复盘区分数据错误、模型错误、竞争误判、时间偏差和随机波动，再决定是否修改方法。

# 研究资料与数据合同

本项目以原件、Markdown、CSV、JSON 为持久资产，DuckDB 在内存中读取 CSV，不保存另一份权威数据。Web 源码在 web/；默认空间 apps/investment-research 是 tools/build-web.mjs 生成的部署副本。旧版历史分析保留，新的研究固定其采用的证据、参数和行情。

## 资料类型、格式和更新责任

| 类型 | 保存位置与格式 | 必填信息 | 更新策略 |
|---|---|---|---|
| 财报、业绩公告、监管披露 | companies/公司/sources/ 原始 PDF；register.csv 登记 | 来源ID、标题、URL、文件名、发布日期、数据期、页码约定、采集时间、SHA256 | 同一文件修订另存版本，不覆写旧原件 |
| 公司计划、业绩指引 | 原始 PDF/网页原文；facts.csv 标为 company_guidance | 目标发布日期、目标期限、阈值或区间、原话定位、采用版本 | 与实绩分开；后续目标修订追加新版本 |
| 行业研究报告 | 可合法留存的 PDF/HTML 原件；无下载权仅保存来源与短摘录 | 机构、方法、样本、地区、sell-in/sell-through、发布日、修订日 | 不复制付费全文；比较前统一范围，不以转载数量当独立证据数 |
| 提取文本与人工摘要 | 原件旁按需生成 .md；标记 extracted 或 analyst_note | 原件ID、提取方法、页码、人工复核状态 | 可重建；不得取代原件，OCR 数字需核对 |
| 结构化财务事实 | 每次分析 facts.csv，UTF-8、RFC4180 引号 | fact_id、metric、period、value、unit、source_id、locator、kind | 原值与口径保存；计划不进入实际业绩列，不对空缺填0 |
| 股价原始数据 | data/market/raw/ 提供方 JSON 原始响应；prices.csv 规范日线 | symbol、date、OHLC、volume、currency、adjustment、provider | 最近窗口重拉、按日期合并、保留更早日期；原始响应按日及摘要留档 |
| 公司与行业事件 | data/events.csv | event_id、event_date、title、source_id、source_url、time_precision | 事实事件与预期事件分开；未知时刻不伪造盘前/盘后 |
| 研究判断与假设 | report.md、claims.csv、assumptions.md | 判断ID、事实ID、反证、有效期；假设与公司计划分开 | 研究正文留档，后续观察追加 verification.md |
| 计算运行 | runs/运行ID/parameters.json、results.csv、manifest.json | 参数、单位、公式版本、引擎版本、输入/输出SHA256 | 固定输入重算，变化建立新运行；结果是派生物 |
| 复盘 | retrospective.md | 原判断时间、观察时点、实绩、误差原因、适用边界 | 历史公司计划复核不冒充本项目当时预测；未到期明确等待 |

本次实际归档小米三份官方 PDF、来源登记、320日窗口内的实际可用日线及事件。网页/行业材料以来源链接和限定摘录入档，不声称已下载全部原件。

## 时间和数字规范

日期用 YYYY-MM-DD；时间用带时区 ISO 8601。行情交易日按 Asia/Hong_Kong，财报期间与公告日期分别保存。来源确切上传日未知就写 unknown，不用访问日冒充发布日。报告 asOf 是信息边界；市场数据当前视图与报告 inputs/prices.csv 快照相互独立。

人民币百万元统一使用 CNY million，不能把千元直接当百万元。数量以辆、股、部注明；货币换算保留 FX 假设和日期。股本区分期末发行股数、扣库存股口径、EPS 加权股数、稀释股数。Non-IFRS 利润与 IFRS 利润分开，不将毛利当净利。

当前行情是腾讯财经未复权的日线，volume 按股保存。已对 2026-06-01 的 OHLCV 与 Yahoo 历史页交叉核对，单日一致不代表全部历史均已独立核实。更新器排除香港当地当天17点之前的未收盘日线；这不是完整交易所日历判断，停牌和节假日不补零。超过最后交易日的数据缺口由状态显示，不冒充实时。

## 更新、幂等和失败恢复

在项目自己的 Python 环境安装 requirements.txt（固定 DuckDB 1.5.6）后：

```bash
python tools/pipeline.py refresh
python tools/pipeline.py dashboard
python tools/pipeline.py calculate --analysis companies/xiaomi/analyses/2026-10-21-growth-evidence
```

refresh 拉取最新窗口，验证价格范围、日期、有限值及重复冲突后，原子替换当前 CSV。相同日期重复更新不增加行；供应商修订会更新当前序列，旧响应及研究快照保留。网络失败、空响应、畸形价格不写空表，status.json 保留最近成功日期和失败原因。并发刷新由独占锁拒绝；异常退出残锁需确认旧进程已停后人工处理，程序不擅自抢锁。

如果 CSV 已保存但 DuckDB 视图生成失败，资料仍有效，只需 dashboard 重建。Web 比较行情摘要，过期视图会提示；不为修复显示重新写原始资料。

本轮提供按需更新命令，不创建未约定频率的后台任务。常用选择是港股交易日收盘后更新；确定频率后可由调度器调用同一入口。Web 刷新页面读取最近已保存数据，页面自身不访问外网，也不触发交易。

## 事件对齐和计算边界

当前试点事件只有日期，采用披露日之后首个可用交易日作为观察首日；基准为披露日当日或之前最后收盘价。记录1日和5交易日价格变化。没有足够前/后窗口时留空，不填0，不回退到别的事件。对盘前已知时间的事件，后续应增加明确时刻和交易所日历规则；本轮不混入该语义。

这是观察窗口，不是因果估计：没有市场基准调整、行业对照或混杂事件控制。价格未复权，不等于含分红总回报；公司行动导致的跳变须另查原始公告。计划将来发生的日期不能冒充真实已发生事件。

## 证据链验收

每条判断引用存在的 fact_id；每项事实指向登记来源和页码；情景假设写参数文件；结果包含公式与输入ID；清单绑定输入、结果和计算脚本摘要。独立复盘案例用2025年3月汽车目标与2025实际交付对照。当前未来预测必须保留未到期状态。

数据接口依据：[腾讯财经日线入口](https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=hk01810,day,,,320,)。第三方接口没有本项目可确认的服务承诺，失效时保留文件，不能静默换数据口径。[DuckDB CSV 说明](https://duckdb.org/docs/current/data/csv/overview)支持显式字段类型；本项目使用该方式避免证券代码、日期和数字被自动误判。

# 手机与消费电子行业方法

## 研究单元
按地区、价位、渠道和时间比较；先确认 sell-in 出货还是 sell-through 终端销售。机构初稿与修订稿保留各自日期。收入=出货量×均价只是起点，产品结构、促销与渠道补贴必须结合毛利验证。

## 必备证据
- 公司财报：收入、出货、均价、毛利、存货、减值、研发与营销。
- 行业原文：市场规模和份额、可比地区、样本与合并品牌范围。
- 供应链与渠道：成本、库存和销售节奏；未获独立证据时列为解释假说。

## 推导与反证
价格上涨但出货下降时，分开计算量、价和结构影响；ASP 上升不自动等于品牌溢价。销量增长但库存、应收和补贴更快增长时，下调需求质量判断。海外份额不能代替海外盈利，必须加入关税、售后、渠道和汇率。

## 验证和复盘
为下一期出货量、毛利率设区间及反证条件，保留预测日期。行业下跌时同时看公司相对市场变化；排名不变而份额下降仍须解释。对比结果写回公司复盘，跨公司重复成立后才改行业方法。

# 汽车行业方法

订单、锁单、生产、批发、交付和上险分别定义。按价位、动力、车型、地区和期间选择同业；不把集团销量直接当同一细分市场竞争。

模型按交付×净均价推收入，再拆单位材料、折旧、产能利用、销售/售后、研发及保修成本。毛利、分部经营利润、净利润和现金流分别验证；重资产扩产需检查资本开支、库存、应收应付和现金储备。

公司目标作为独立版本的计划：发布日期、适用年、阈值或区间、后续修订。半年完成率仅代表进度，需季节性与产能证据后才能推断全年。超过一个早期阈值不等于达到最终修订目标。

反证包括交付增长而毛利/现金下降、降价依赖、质量及售后成本上升。发生事故或监管事件时引用可核实原文，不从股价变化推断责任。复盘区分需求误判、产能约束、价格竞争与成本兑现。

# 互联网平台与AI投入方法

按用户、参与度、付费/广告变现、单用户收入和单位服务成本拆业务。集团收入与某产品增长不可互相替代；平台竞争包含时间、预算和替代渠道。

AI投入分研发费用、资本开支、折旧、推理成本和外购服务；公司多年研发计划不等于AI专属预算。把投入转换成收入或效率收益需要独立证据：客户付费、留存、转化、单位成本、毛利和现金回收。不得用模型排名直接推断商业回报。

估值分成熟现金流与新业务，集团费用、内部交易、净现金和投资资产避免重复计入。回购与股权激励同时进入每股推导。监管、内容供给、流量入口和算力成本分别设反证。

复盘先比较当时预测的经营指标，再看买入价格和市场回报；未披露AI收入时保留未拆分，不用集团增长虚构归因。
