# 可复用输入、精确覆盖与版本规则

适用于双企业及后续企业的资料获取。先读[输入适用性规则](data-fitness.md)，操作和请求合同以 `research capabilities --json`、`research schema <合同名> --json` 为准。工作空间根保持共同入口，应用调用共享服务，不为公司复制引擎或另建事实库。

## 从规格到输入包

1. 使用 `research/input-profiles/<profile-id>/v1.json` 声明对象、准确期间/时点、指标、维度和口径；`expected_keys` 是需要的数据身份，不能用总行数抵消缺期。`comparison_groups` 只绑定需要一起比较或连接的输入，不强制所有不同指标同口径。
2. `research data profile-audit --request <规格文件> --json` 核对精确预期键，`profile-assess` 检查用途及跨键口径。`missing/ambiguous/unavailable` 以及 `limited/blocked` 均须报告，不能通过拆分需求隐藏单位差异。选取其他受限研究范围时保存独立规格并保留原需求。
3. 先查归档原件，再使用 `source-discover` 的已登记 binding 和有界参数发现资料；`acquisition-plan` 建立任务，`acquisition-run` 分阶段获取、提取、复核、准入，`acquisition-status` 查询进展。发现或下载成功不等于提取完成；`pending`、待审核和失败不得报告为数据就绪。
4. 来源能力维护在 `research/source-providers`，对象映射维护在 `research/source-bindings`。复用对应提供方适配器；新提供方可以增加经过测试的解析器，但禁止在通用引擎添加公司名称特判。认证、归档和来源限制不因换URL/import路径而绕过。
5. 原始披露值与数量级保留。`normalize-inputs` 的整理结果为派生结果，不能覆盖原始观测。IFRS/调整后、归母/总利润、单季/累计、存量/流量、股类、产品和地域不因数值单位相同而自动兼容。
6. `freeze-inputs` 固定研究输入版本，`verify-bundle` 核验已保存包。冻结成功不表示用途ready；必须保留包内适用性结论和缺口。确定性变换应绑定原件摘要、合同、代码与依赖版本；AI提取保留实际可知的模型/提示/响应和复核，不编造模型标识。

## 时间与资料修订

- 原件正文逐条提取真实事件/业务期间，不把整份年度报告内所有事件归到该年末。
- `revise-metadata` 只提交有原件定位及复核依据的公开时间断言。新修订追加保存，禁止编辑旧document.json或历史批次。
- 只有发布日期时保留 `precision=date`、来源日期和IANA时区；保守可用上界不是来源真实发布时间。未知日期不填零点，不由文件迁移URL猜公告日。
- 历史重建可利用后来取得的原始公开证据；`live_observed`仍要求系统当时已经观察、登记相应证据。后来重述不能静默替代过去原版。

## 人工语义核验

财务和经营候选在准入前核对原件、物理页、表头/脚注、单位、期间和业务维度。资产负债、现金变化及分部合计勾稽应说明舍入/未分配项。经营出货不等于零售，活跃用户不等于设备数，订单不等于交付；未进入业务时期是不适用或未披露，不能自动补零。

当前工具不认证投资因子有效性，也不自动确认审核者身份。公开来源受限时保留受影响用途和解除条件，不把记录缺口当作补齐数据。批量任务恢复依据Git中的任务/回执，临时缓存不能成为唯一工作历史。

采集任务可用 `submissions[item_id].skip_reason` 明确跳过尚未准入/验证的项，必须记录实际理由。终态 `completed_with_skips` 是含跳过项的任务结束，不是研究覆盖完成；CLI 返回非完整状态码 3，继续检查输入规格。跳过事件不可抹除，重新处理需另建选择该项的任务。候选更正使用已支持的 `supersedes` 和 `parser_version` 字段保留修订链。
