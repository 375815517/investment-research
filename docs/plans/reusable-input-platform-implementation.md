# 可复用研究输入平台实施计划（已实施，按用途保留数据缺口）

日期：2026-10-30（Asia/Shanghai）。依据[多角色评估](factor-input-readiness.md)。用户已于2026-10-30批准本计划，包括腾讯00700/HKD主证券与A–F范围。工程与真实双企业流程已实施，逐项结果见[最终验收](../verification/reusable-input-platform.md)；数据就绪程度按精确需求保留缺口。

## 1. 本轮目标与验收边界

把现有样例级数据获取闭环升级为可复用能力：给定公司、时期和研究输入需求，通过统一工具完成发现、获取、提取、审核、准入、精确覆盖、用途评估与可重放归档。

三个独立交付目标：

1. 工程可复用：换企业/期间不重写引擎或工作流，遇到失败、重复、改版、重述能恢复并留下证据。
2. 数据可核实：原件、原始披露值、确定性整理值、公开时间和版本分别可追溯；完整性按预期业务键而非总行数判断。
3. 用途可判断：可生成财务、经营、价量和估值研究输入包，明确ready/limited/blocked及依赖缺口。数据可计算不等于已发现有效因子。

本轮不实施预测训练、因子挖掘/收益回测、交易执行、全市场股票池、全网舆情、定时调度或公网多用户服务。政策/新闻沿用现有有界资料能力及时间规则，本轮不扩成全历史语料工程。

## 3. 首批数据包及字段

字段均来自原件，按指标字典保存来源标签、统一语义及单位，保留“未披露/未取得/不适用/待核验”区别。最终精确字段清单在阶段A形成版本；不允许为了提升完成率静默删除需求。

### 财务核心包

- 损益：收入、销售成本、毛利、经营利润、财务成本、所得税、年度/期间利润、归母利润、基本/稀释EPS。
- 资产负债：总资产、总负债、总权益、归母权益、现金及现金等价物、流动资产/负债、存货、应收/应付、短期/长期借款；缺具体披露时不猜值。
- 现金流：经营/投资/融资现金流净额、期初/期末现金、汇率影响；购建资产现金支出按原披露范围保存，不把不同来源“资本开支”默认为同义。
- 会计与版本：IFRS/来源实际准则、合并范围、原始/重述/调整口径、期间类型、审计身份及对应原件。
- 派生准备：累计转单季、单位归一、期初期末平均值等只定义转换合同并验证，派生结果单独保存，不覆盖来源值。

### 分部与经营包

- 共同骨架：分部/产品/地区维度及有效期，分部收入、利润或毛利及其原始定义；不可跨不同分部定义直接比较。
- 小米：手机收入/出货、IoT分部与设备口径、互联网收入/MAU、汽车交付/收入/毛利；集团汽车相关新业务分部与EV本体分开。
- 腾讯：按各期披露的业务分部收入/利润，以及微信等产品活跃用户、付费用户等可核实经营量；产品、合并统计范围和活跃周期须明确。
- 不强制两家公司有同一套业务指标；共有字段复用合同，特有字段通过字典与维度配置表达。

### 价量、公司行动与估值输入包

- OHLC、成交量/额、币种、单位、交易日/停牌状态、价格调整类型及来源版本。
- 分红、拆并股等事件的公告、除权、生效/支付日期、比例/金额和适用股类；复杂分派保留事件身份与估值缺口。
- 指数基准、股份类别、有效股数、估值利润窗口；跨币种估值必须有相应汇率输入。
- 卖空成交量/额与同counter总量/额、须申报淡仓及报告范围；自由流通方法未核实不生成比率。
- 供应商PE与平台可计算PE的输入分别保存，不以供应商标签代替盈利定义。多头比例/分布未定义或无明细时保持blocked。

## 4. 实施阶段

### A：冻结合同、字典和精确需求

**实现位置：** packages/domain、research/datasets、research/指标与单位定义（具体目录在架构决定中固定）。

- 保留现有FinancialFact旧版本，增加向后兼容的维度化财务合同和独立OperatingObservation，共享值、单位、期间、证据及维度组件。
- 定义stock/flow、瞬时时点/区间、年度/中期/单季/累计；货币仅在适用时必填，每股/数量/人数/设备/百分比有明确量纲。
- 指标字典绑定含义、合法单位/维度、允许变换和必需证据；不通过拼接metric_id隐藏维度。
- 扩展现有ExpectationSet：对象×精确期间/时点×指标×维度×口径/版本选择规则；分开原件覆盖与结构化字段覆盖。
- 新建InputRequirementProfile，定义用途、依赖/比较组、连接键、连接基数、时间对齐、来源选择和阻断条件。

**交付：** 版本化合同/schema、两家公司输入规格、字段目录、旧数据兼容策略、正负样例。

**验收：** 收入、现金余额、EPS、手机出货、MAU均可正确表达；错币种/股类/期间不能顶替预期键；同一来源重复行不能弥补缺年；旧52条财务记录仍可读且文件不被改写。

### B：补比较门禁与时间版本

**实现位置：** packages/engine、packages/repository、packages/domain。

- 同comparison_group跨requirements检查单位、期间、维度与连接基数；独立描述组不强制互相同口径。
- 数量级转换使用Decimal及登记规则；汇率转换另需汇率证据；保存输入/规则版本及输出，不把“标准化”当原始披露。
- 增加DocumentMetadataRevision：旧/新断言、证据、发布时间精度/区间、审核和登记时间；不修改原document.json。
- 分开事件/报告期间、公开可知、系统首次观察与修订登记；historical_reconstruction和live_observed分别筛选。
- 日期级公开证据采用有依据的区间和保守可用上界/下一可交易时点；未知日期阻断，不自动填午夜。

**交付：** 跨需求比较服务、时间修订工作流、可查询修订链、按用途质量报告。

**验收：** 同一组千元/百万元无论合并还是拆分请求都得出一致判断；有转换记录后方可比较；半年/全年、总利润/归母利润、错股类阻断；新时间证据可使历史重建正确可用但不能伪装过去已采集；旧冻结输入包不改变。

### C：通用来源发现与任务编排

**实现位置：** packages/connectors、packages/engine、research/sources、research对象映射。

- 拆开SourceCapability、对象映射、DiscoveryRequest/Result及具体文档身份；固定日报日期和年报URL不再承担提供方身份。
- 复用现有HTTP下载、鉴权、限制、重试与解析器；补有界发现、分页/游标、期间窗口、来源级节流和持久化retry_at。
- 统一下载与归档大小限制；模板页/空响应/改版分别检查，不以HTTP200认定成功。
- AcquisitionTask统一发现→获取→提取→复核→入库→验证状态；待审核不是失败，也不是已完成。
- 已有原件优先提取；任务与关键回执纳入Git运行清单，临时缓存仍可重建，支持干净克隆恢复。
- 新的提供方若需要新网页解析器，可在connectors中增加有测试的适配器；禁止将腾讯/小米特判写进通用执行层。

**交付：** 来源能力配置、发现清单、批量任务工具、失败/重试回执和统一恢复命令。

**验收：** 换年份无需复制整套配置/脚本；新企业只改映射/字典及必要来源适配；分页中断、429、404、重复、模板页、来源改版均能明确停留在正确阶段并恢复；未知许可/认证限制不通过备用路径绕过。

### D：小米真实数据补齐

**依赖：** A、B通过；C完成对应来源适配。可先用现有原件做D的提取验证。

- 盘点八年年报已有表格/字段；先2024贯穿流程，再2025及早期年份。
- 补核心三表、归母/EPS、分部和经营数据；正文事件逐条识别真实时期，避免把2026事件归到2025年末。
- 发现并归档中期/季度资料、原始公告时间；按实际披露制度冻结缺期清单。
- 补交易状态、公司行动、基准、股本及所需市场窗口；核实价量单位与调整口径，保留跨来源差异。
- 运行勾稽：资产=负债+权益、现金变动衔接、分部与集团合计；保留舍入、未分配项和口径差异解释。

**交付：** 小米四类输入包、逐字段/逐期覆盖表、语义复核记录、勾稽报告、尚未解决的来源缺口。

**验收：** 原件、结构化和历史可用率分别报告；每个必需预期键有状态、原因及证据。只有全部必需输入通过的具体用途才ready；有未取得/待核验不宣称数据目标全部完成。

### E：腾讯复用与恢复验收

**依赖：** 主证券随计划确认；A–C接口稳定。映射/来源调查可与小米补齐并行，完整验收在D后进行。

- 使用同一输入规格骨架、任务命令、审核/准入与覆盖评估；业务特有维度通过配置表达。
- 先2024和2025年度进行跨公司/跨期验收，再补2018–2023及已公开中期/季度资料和既定行情范围。
- 独立检查腾讯业务分部/产品统计，不把小米经营定义直接迁移。
- 注入故障：断网/429、分页中断、原件重复、响应改版、单位变化、重述、发布时间更正、待复核、跨克隆恢复。

**交付：** 腾讯对应输入包、双企业复用对照、故障恢复记录、干净克隆重放报告。

**验收：** 通用引擎无公司分支；相同请求重跑不产生重复正式观测；恢复不依赖原机器临时文件；旧研究包的摘要/查询结果稳定。两家公司有差异的来源/业务规则被显式记录，不以统一结构掩盖口径差异。

### F：统一入口、文档与最终验收

**实现位置：** apps/cli、apps/api、apps/web、ai/skills与ai/rules、docs。

- 所有新操作通过同一应用服务；页面呈现来源、任务阶段、具体缺键、修订及用途状态，避免只有一个总完成率。
- 更新数据规划/获取/复核/研究Skills：需求先行、先查本地、按缺口获取、候选复核、精确覆盖、用途判断、冻结输入包。
- TransformationRun固定原件摘要、schema、解析/转换代码版本、依赖锁、参数及输出摘要；AI候选保留实际可取得的宿主/模型标识、提示/响应和审核，不编造模型版本。
- 输入包纳入Git，保留旧记录；评估仓库增长和克隆耗时，未经单独设计不迁出Git权威档案。
- 仅选择性提交/推送本轮文件，保留既有legacy删除；接口功能、数据事实和来源限制分别验收。

**交付：** CLI/API/web演示、Skills、完整文档、测试报告、版本化双公司输入包及最终差距清单。

**验收：** 三入口同一请求得到相同业务结果；新克隆可恢复任务并重放确定性整理；调用新AI模型不改变历史候选；所有关键负例通过，真实数据逐项验收。工程完成和数据充分性分别结论，不用测试数量替代研究有效性。

## 5. 依赖及多角色协作

顺序：A → B/C → D → E → F。F的接口/文档随前面阶段增量完成，不积压到最后；C的来源调查可与B并行，正式准入必须使用已确定的合同。

- 架构/领域Agent：A及兼容性、边界与迁移。
- 数据治理Agent：B、精确覆盖、修订及负例。
- 来源工程Agent：C、连接器、任务恢复。
- 财务/行业Agent：D/E候选提取、口径与勾稽；提取与独立复核尽量由不同角色承担。
- 应用/AI Agent：F、入口及Skills。
- 独立验证Agent：跨期/跨企业及故障注入，复核不可用结论。

共享合同先由主代理整合；Agent按文件/模块分工，避免并行改同一合同。关键阶段保存可审核的diff、实际命令与回执。

## 6. 完成判据与暂停条件

- **工程完成**：声明模块、接口及正负测试、真实双企业流程、恢复与文档全部通过。
- **某输入包就绪**：该用途全部必需输入、语义/期间/维度/可知性与转换约束通过；非必需缺口展示但不擅自阻断其他已就绪用途。
- **数据仍阻塞**：来源不可取得、定义未成立或缺证据时，保留原需求、受影响用途与解除条件；不能以“已记录缺口”冒充该数据已补齐。
- 来源需要新付费凭据、范围发生实质扩大或需要改变Git权威存储时，先提出具体方案；一般实现选择、修复、离线测试、已授权公开资料采集无需反复确认。
- 数据口径错误或未知时期立即停止相关批次准入；其他独立模块继续，不让错误值污染正式档案。

本计划审核要点：目标是否接受；腾讯主证券是否采用00700/HKD；首轮数据时间范围和字段包是否适合；是否按A–F阶段执行。批准计划不代表对来源可得性作承诺，也不把两家公司样例当作因子统计有效性证明。
