# 从输入样例闭环到指标与因子研究：多角色评估

评估日期：2026-10-30（Asia/Shanghai）。基于提交c58b321的代码和正式输入。此次是系统性分析阶段：实际重跑数据适用性检查并审查代码，不将建议模块写成已实现，不开始训练或报告因子有效性。

## 1. 总体判断

现有平台已具备可复用的证据归档、候选审核、不可覆盖准入、查询及有限质量评估；它是研究输入基础设施的初版，不是已经验收的通用因子数据平台。

可以设计指标合同、提出有经济含义的假设，并做有限的事后原型。尚不能凭当前数据宣称完成系统性因子发现、无前视历史验证或可泛化预测。应按研究用途补依赖，不要求所有辅助资料齐全后才做任何研究，也不能把样本成功推广为全历史成功。

## 3. 哪些研究现在可以做

| 研究用途 | 当前判断 | 补齐前必须保留的边界 |
| --- | --- | --- |
| 指标定义与经济机制假设 | 可以 | 固定输入、单位、期间、公式、缺失和可知性规则；定义存在不代表可计算或有效 |
| 年度收入同比、毛利率、经营利润率的事后原型 | 有限可做 | 选择同一期间/币种/单位/合并口径和明确来源版本；8年样本不用于证明预测能力 |
| 价量图表、来源口径下的探索 | 有限可做 | 明示provider-native；不能升级为复权总回报、超额收益或可靠交易结果 |
| 单日卖空成交占比 | 指定同表输入可计算 | 流量不是持仓；非来源直接披露值，不能用1减它得到多头比例 |
| 动量、波动、流动性等时序因子验证 | 尚未就绪 | 先核实行情语义、公司行动、交易状态、基准和可交易时点 |
| ROE/ROIC、现金质量、TTM估值等财务因子 | 尚未就绪 | 需相应三表、归母/调整口径、期初期末或TTM期间、股类/股本和公告时点 |
| 政策/舆情/竞争语义因子验证 | 尚未就绪 | 需有边界的历史语料、原始版本、公开时间、去重、标签定义及人工核验样本 |
| 横截面因子发现 | 尚未就绪 | 需按历史时点定义多企业股票池、纳入/退出记录、同行与基准，不只保留今天存续样本 |

因子检验还需预先定义标签、交易延迟、基准、费用及样本划分；采用时间顺序样本外验证，处理重叠标签和多重试验。它们属于后续研究执行层，但输入必须能提供对应证据和时点，不能临到回测时补猜。

## 4. 缺口的四种性质

### 原件已存在，尚未结构化

2025年报已有资产负债、归母利润、出货、MAU、IoT、分部收入和毛利等资料；八年年报也可作为提取起点。应先盘点原件中的字段位置并逐项提取，不把“未提取”当成必须重新联网寻找。分部调整、业务进入时间、季度累计与单季必须分别标记。2025年报正文还包含2026年事件和截至2026年2月的排名；不能把整份报告中所有声明统一标成2025年末。事件期间须逐条从原文确认。

### 需要可复用发现与补采

中期/季度业绩、公司行动、基准、历史股份和卖空、竞争及政策版本需要有界发现清单、分页或日期窗口以及重跑回执。当前一些接入是固定到公司/年度/日期的来源配置；成功获取小米样本不证明换公司或换时间后能自动补齐。

### 需要补充或纠正证据元数据

原件去重会沿用首次登记公开时间，后来取得的公开时间证据留在回执，尚无审核后的元数据版本更正通道。应增加追加式修订，而不是编辑document.json。只知道官方发布日期时保存日期精度、时区和有依据的可知区间，按保守上界/下一可交易时点使用；不伪造秒级时间，也不要求日期证据永远不可用于年/月研究。今日首次获取仍不能冒充历史live_observed。

### 定义或可得性不成立

“全市场多头比例”“投资者看多分布”不是从成交买卖两端或1减卖空自然得出的字段。先定义工具、统计群体、披露门槛、日期、金额/股数权重和分组；若无可核实明细就保持不可用，不为凑齐字段造值。政策与舆情没有可证明的全网全集，应报告实际语料范围及偏差。

## 5. 可复用的最小工程补齐

保持现有apps → packages执行服务 → Git权威档案的结构，扩展现有合同，不并建第二套事实库。下列为待实施设计，不是当前CLI已有命令。

| 模块 | 最小职责与建议合同 | 验收条件 |
| --- | --- | --- |
| 指标输入规格 | 为每个指标定义输入字段、对象、维度、期间、知识模式、比较/依赖组、预期键与允许缺失；只定义输入需求，不在本轮生成预测 | 给定指标和区间，可列出每项依赖、口径及阻断原因；独立需求不能靠任意min-count冒充完整 |
| 财务/经营观测合同 | 扩展FinancialFact，或增加明确的OperatingObservation；支持stock/flow、期间类型、测量单位、每股、会计/调整口径、分部/产品/地区及来源版本 | 同时表达营收、期末现金、EPS、手机出货和MAU；不把股数/用户数塞成货币，不把维度编码到随意metric_id字符串 |
| 指标与单位目录 | metric定义固定经济含义、合法维度、原始单位和标准转换规则，保留原始值；跨记录比较须显式绑定comparison_group | 千元/百万元可以有记录地归一；归母/总利润、单季/累计、A/B股混用阻断；互不相关的指标不误判为必须同口径 |
| 来源与对象绑定 | 区分provider能力/connector、证券映射、查询参数和获取到的文档身份；复用现有连接器、超时、重试、鉴权和归档限制 | 增加已确认的新企业只补映射/定义；换年度不复制一套解析代码；来源ID不因每日报价日期不断复制配置 |
| 来源发现与采集规划 | 有界discover清单列报告/版本/时间和证据；分页/窗口、动态日期参数、失败原因、续跑和请求摘要统一保存 | 发现链接、下载完成、解析完成分别计数；404/429/模板页不算有效观测；中断重跑不重复准入历史 |
| 时间与修订 | 追加式metadata修订，公开时间精度/证据、系统观察时间、有效期与版本选择分开；保留原始报告及重述 | 后补时间证据能通过审核解除适用性阻断，旧截止查询结果有版本可追溯；不能用重述或未来证据改写过去 |
| 精确覆盖 | 扩展现有ExpectationSet，按对象×期间×字段×维度×来源版本匹配；市场观测/资料目录也有相应预期键 | 删除指定季度、放入错误币种/半年行、重复同一行，都不能被记录总数填平；尚未到期和非适用不算来源故障 |
| 质量与用途门禁 | 跨依赖组检查单位/期间/股类/可知性；区分字段覆盖、时间覆盖、版本覆盖、来源核实与用途可用 | audit满足但依赖无法比较时，不能宣布该指标input-ready；未知检查列为未评估，不自动通过 |
| 可重放研究输入包 | 固定研究问题、公司池版本、cutoff、所选记录/批次/SHA、指标输入规格、转换/解析代码版本和依赖锁；语义提取记录宿主/模型/提示版本与人工复核范围 | 同一输入包能复现确定性变换，模型变化不静默改变历史；新原件到来不改变已冻结研究 |
| 运维与AI工作流 | 统一缺口清单和source attempt状态，区分未发现/未取得/未提取/待复核/口径未知/历史不可知；AI调用统一服务 | CLI/API/网页/Skills同一需求返回同一状态；无需定时器，研究启动先查缺口，按需补齐并重验 |

现有FinancialFact只有货币、合并/单体和起止日期等字段；不要直接把新增财务/经营概念塞进当前自由metric_id后宣称合同已支持。数值候选仍由AI理解提取，单位转换、覆盖判定、版本选择及计算交给确定性执行层。

## 6. 本轮发现的具体门禁不足

`assess_inputs`主要在单个requirement内部检查混合口径。将2024收入的千元与百万元两个来源合在同一需求中会阻断，拆成两个需求则不再报混单位。[本轮复现记录](../../data/outputs/research-records/xiaomi-factor-input-review-20261030/comparison-group-reproduction.json)保存实际请求与返回。两个独立描述需求本身无需阻断，但若下游要比较或相除，当前请求没有显式比较组，便无法保证跨需求正确。

因此应增加比较/依赖关系，而非无差别全局合并所有记录。年度32/32检查目前也只绑定年内日期、metric/source和最少行数，不能作为通用的精确年度期间、合并范围和币种合同。应复用已有财务ExpectationSet能力并扩展到其余数据类。

额外的工程一致性问题：下载连接器允许最高50MB，但导入固定上限32MiB，须统一为请求协商的有效边界，否则新来源可能下载成功后归档失败。已有有限超时/重试/部分Retry-After处理应复用，补的是来源级节流、分页游标和持久化续跑，不是重写HTTP客户端。

现有ready/limited/blocked不能直接解释成factor-ready：尚未检查股票池、标签、基准、重叠样本、公司行动、下游转换和模型试验。测试185项证明已测工程行为，不证明所有数据完整或因子有效。

## 7. 落地顺序与完成标准

**第一批：补合同和门禁。** 完成维度化观测、单位/指标目录、精确预期键、比较组和公开时间修订。用上述错误单位、混期间、错股类、日期精度、未来版本的负例验收；先阻止错误使用，再扩大采集规模。

**第二批：补小米第一组可研究输入。** 从已归档年报提取基本三表/归母利润/股数和分部经营，发现相应中期/季度资料；补行情口径、公司行动、交易状态、基准及公告可知性。分别交付价量、财务质量、估值、经营四类输入包，明确每类范围与不能完成的部分。不要因辅助新闻仍不全阻断已满足依赖的年度描述性指标。

**第三批：验证跨对象复用。** 选择另一家用户确认主证券的企业，复用同一采集与准入流程，改变配置/映射即可获取相同类别资料。再在明确产品/地区/时期的同行范围内扩展；历史股票池及退出样本是横截面阶段的验收要求，不为单企业研究强行增加多个主证券。

**第四批：进入指标/因子实验。** 输入包通过对应用途门禁后，才实现指标计算、标签及样本外实验。先验证单公司有经济含义的假设；横截面因子另设样本池与覆盖条件。结论必须区分可计算、统计相关、样本外稳定和可交易，不用一个“完成”状态替代。

系统复用验收的最小组合：同来源换企业、同企业换期间、同文档重采、来源改版、断网恢复、旧报告重述、日期级公告证据、错误单位/维度、缺一个预期键、跨需求比较，以及固定输入包重放。每一项都要有失败状态与证据，而不只是成功样例。财务还要验证资产=负债+权益、现金流与余额衔接、分部与集团勾稽，明确舍入/未分配项容差；累计转单季必须绑定同口径的两个输入，不能对缺期或重述随意相减。

## 8. 多角色分工与本轮边界

量化研究员/基金经理审查有效样本与因子用途；数仓/治理角色重跑覆盖和历史适用性并复现比较组缺口；软件架构角色审查来源接入复用、任务恢复与版本重放；财务/行业角色核对已有原件可提取内容及业务口径。主代理整合为上述共同依赖和验收顺序。

本轮保存分析与可复核运行记录；没有宣称建议模块已实现，没有修改正式输入、批量补采或开始因子训练。下一阶段应以本文件的第一批、第二批作为数据工程实施范围。
