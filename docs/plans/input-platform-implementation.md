# 输入平台工程实施与验收计划

日期：2026-10-30。依据：[输入基线 v1](../architecture/input-data-baseline.md)。本计划将多 Agent 讨论落实为交付及验收项，最终执行状态以 [验收记录](../verification/input-platform-v1.md) 为准。计划存在不代表已实现；不改变输出目录设计。

## 目标与执行边界

实现可安装的 Python workspace、共享应用服务、CLI、可靠文件归档与入库、AI 候选复核及宿主文件适配。以明确的合成离线样本和模拟网络验收，不将样本写入真实企业档案。真实小米主证券必须由用户首次确认，真实来源需单独验证覆盖、许可和口径；未确认或不可达只阻塞该阶段，不阻塞公共基建。

## 依赖与模块职责

CLI负责解析与输出；engine组织用例，domain定义合同，repository负责路径/内容/版本，connectors负责获取与来源解析。宿主安装逻辑只在ai/tooling实现。Skills引用真实能力，不另写计算、路径或状态机。

通用操作信封包括协议版本、操作ID、状态、摘要、产物引用、覆盖、问题与下一步。资料与大表以文件引用传递。来源、schema、解析器和候选版本固定；配置不允许任意Python脚本执行。

共享协议结构单份维护并导出schema。数据集使用有限且可检查的合同；不得引入无测试的通用规则语言。采集、质量和登记状态分别处理。Git提交/推送不由fetch暗中触发。

## 分阶段执行

1. 写入本计划，确定模块接口和文件所有权；保持既有legacy删除未变。
2. 并行实现公共包、CLI、来源基础及AI文件适配；根工程统一依赖。
3. 集成后先运行离线测试，修复真实失败，再做类型、格式、构建和干净安装。
4. 使用合成行情与财务原文跑完整CLI闭环，核对正式路径、复核和历史时点。
5. 验证适配文件及引用。宿主实际发现与调用仅在真实宿主可用时登记通过。
6. 记录所有通过、限制和阻塞；仅显式文件集合进入提交，保留用户已有修改。

## 首批回归场景

重复原件、多渠道回执、同原件重新解析、同URL新内容、多证券响应、缺字段/缺交易日、HTTP错误页、单位与业务范围歧义、候选复核后修改、计划失效、写入中断、冲突ID、索引重建、历史公开/采集时间过滤、工作区外调用、AI安装冲突和相对链接。

默认CI不联网、不调用真实模型。真实数据/模型测试必须单独运行并记录时点；不能用fixture通过代替真实源就绪。暂不引入微服务、分布式队列、图数据库、全市场高频或默认LFS。
