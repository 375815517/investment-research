# 多源历史输入合同与验收

范围是原始资料、可核实整合记录和获取覆盖，不包含收益预测或投资结论。需求清单先于采集；工具实际接受的字段以 `research schema` 为准。下表是每类资料必须核实的语义合同，不能据此宣称尚未接入的渠道已经可用。

## 需求与渠道覆盖

每项需求固定对象、业务/产品、地区、期间、历史知识模式、所需资料或字段，以及完成标准。需求指向候选渠道，渠道记录实际检索区间、查询条件、访问时间、所得原件引用及未得原因。一个来源下载成功，只证明该次请求取得资料，不证明行业、新闻或政策全量覆盖。

获取情况分别记录可取得、付费限制、认证缺失、网络阻塞、已删除/不可取得、尚未检索、覆盖未知。不能把这些状态降为“没有相关信息”。没有权威发布清单或可核实的有限需求时，不计算完整率；新闻搜索结果数不是总体分母。付费、不可取得等是渠道结果，不能擅自塞进不支持该枚举的工具 status 字段。使用当前 schema 已有字段；不支持的需求维度保存在明确标为人工规划的研究记录中。

同一区间各类资料按自身披露频率获取，不要求每天都有政策或新闻。完成验收区分原件取得、提取完成、审核通过和预定义需求已覆盖；不同渠道独立报告，不能以行情齐全代表所有输入齐全。

## 内容与证据

| 数据类别 | 可登记的证据事实 | 不能偷换的结论 | 必查内容 |
| --- | --- | --- | --- |
| 财报/公告 | 某版本报告披露某期间的数值、公司发布某项目标 | 披露值不自动等于独立审计证实；目标不等于实际值 | 累计/单季、合并范围、审计状态、重述、币种、单位；预测与调整后指标单独标记 |
| 政策 | 机关发布的原文、法律状态、生效与失效日期、适用条件 | 政策支持某行业不证明小米已符合资格或取得收益 | 发文号、机关、地区、附件、修订/废止链；征求意见稿不能当已生效法规 |
| 新闻/舆情 | 某主体在某时发表的报道、评论、传闻或澄清 | 报道主张不自动为事件事实；小样本情绪不是市场整体舆情 | 首发、更新、撤稿、说话主体、主张类型、根来源、相互独立性 |
| 行业/竞争 | 有定义样本和统计口径的市场数据、竞争者披露与产品事实 | 不同市场/期间/产品口径不能直接排名；缺失竞争者不等于份额为零 | 地区、产品、出货/销量/激活量、期间、统计样本、厂商集团口径、市场份额分母 |

“原文存在该陈述”与“该陈述经独立核实成立”分开记录。来源陈述保存原文定位和摘录；AI 推断单独保存依据、假设和待验证项，不进入实际观测。管理层愿景、媒体评论、政策意图的存在是可核实的，但其内容的实现不是既成事实。证据强度以核实范围表达，不赋予无定义的置信分。

## 市场字段防混淆

- 卖空成交额/成交量及其占当日成交的比例是交易流量。监管披露的须申报淡仓是特定门槛、范围和报告日的持仓存量。二者不能拼为同一多空序列。
- `1 - 卖空成交占比` 只可能表示该口径下非卖空成交占比，不能标为多头比例；成交有买卖双方，不能据此推出净看多资金。没有直接且定义明确的多头数据时记未知。
- PE 必须保留 TTM/静态年度/预测、利润归属与调整口径、报告期、价格时点、每股/总市值方式、币种及来源。亏损、零利润、缺失与“不适用”分开；供应商 PE 只登记供应商披露值，未披露口径则标未知，不倒推成已验证算法。
- 已发行股数、流通在外股数、自由流通股数、上市类别股数、库存股不同。小米不同类别的投票权和经济权益不能因名称相近混算；按证券类别、日期及来源定义保存。PE 分母与股数类型必须匹配，不能用港股一类股的股数配集团全部利润而不解释。

## 可执行流程和验收情景

先检查 capabilities/schema，按当前实现创建需求、原件和候选；通过 validate/review/ingest 等正式工具准入，再查同一需求覆盖。新数据集必须先有合同、程序校验和测试，再在 Skill 中允许使用；不能靠提示词绕过未知字段。

最低验收：转载同源去重；愿景不能作 reported_actual；政策草案不作现行政策；缺原文保持缺口；相同期间而市场口径不同的份额不合并；付费未取得不变成零；卖空与净淡仓不合并；PE 未知口径不冒充 TTM；缺股类不自动视为自由流通；历史补采不能伪造当时首次观察时间。

宿主验证只证明实际调用路径。`investment_ai.probe` 对新数据集复用同一缺口查询协议并保留真实状态，不自行解释某领域“应当完整”；显式调用成功、原生发现、语义正确分别验证。

## 本轮实际工具边界

新增合同为 DocumentFact / MarketObservation / RatioDenominator，数据集名为 document-facts / market-observations。DocumentFact 的 assertion_type 固定 source_assertion；MarketObservation 的 record_kind 固定 source_reported，不实现推断及估值计算。not_disclosed 必须由来源证明，平台没有找到不等于来源未披露。比例记录须提供分母定义、期间、市场、股类、document_id 和定位。

两类新数据走 prepare/validate/review/ingest，强制复核；coverage 查询实际已有记录，未实现 detect-gaps/ensure 自动完整性判断。需求清单与渠道覆盖先以明确标注的规划/获取证据保存，不声称已有多源全自动覆盖调度器。probe 新增 `--operation coverage`，仅验收调用与读取，返回 completeness=not_assessed；旧默认 detect-gaps 不变。

有限需求清单可调用 `research data audit-inputs --request requirements.json --json`：请求包含 requirements 数组，每项 dataset_id、subject_id、start、end 及 minimum_records（默认1），可按 source_id、metric_id、document_kind 或 price_basis 筛选；历史模式在顶层声明 knowledge_mode 和 information_cutoff。该操作仅检查声明的样本/记录需求，不能证明全网渠道完整；市场 null 值不满足数值需求，不能把取得缺失说明算取得值。渠道未得原因仍单独保存。
