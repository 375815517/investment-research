# 数据平台闭环：目标、设计与验收

日期：2026-10-30。用户已确认本轮范围：原始资料及清洗整合后的数据平台；不包含指标、预测、评估和复盘。定时调度暂缓，检测缺口与按需补采必须实现。本计划替代将真实数据验收笼统推迟到后续阶段的做法；此前 v0.1 验收仍只说明已完成的离线基建。

## 目标

人或通用 Agent 从研究对象、期间和信息截止点出发，能知道需要哪些数据、已经有什么、缺什么及原因；通过统一工具取得原件、清洗核验并入库，复查后得到可追溯的整合数据。Git 是事实与证据的持久化载体。小米港股 01810/HKD 是本次真实验收对象，不在通用代码中硬编码。

## 分层与执行路径

- research：数据集、来源、覆盖与延迟规则定义。
- data/inputs：原件、采集回执、交易日历、披露预期、业务记录。事实单份保存，关联查询生成。
- domain/repository/connectors/engine：合同、版本存取、采集解析、覆盖检测与有界执行。新增检测模块从已有 Service 拆出，避免继续堆积单一文件。
- CLI、HTTP API、网页和可选 MCP：调用同一应用用例；不重复计算完整性、不让网页直接改正式文件。
- ai：Skills 指导检测、补采与复核，宿主适配复用权威方法；文件安装、显式调用与原生发现分别验收。

流程：需求 → detect_gaps → ensure_plan → ensure_apply → 原有归档/候选/校验/复核/入库 → 同需求再次检测。读取覆盖不隐式联网。计划绑定数据与规则版本，执行有请求上限，失败不无限重试。财务原文理解由 Agent 执行，程序不自动替代语义复核。

## 检测规则

| 检测 | 判定依据与处理 |
| --- | --- |
| 行情范围 | 有证据且带覆盖区间的交易日历；不能用普通工作日推算节假日 |
| 收盘与延迟 | 按市场时区、正常/半日收盘时间、来源延迟判断到期；未到期不报漏采 |
| 停牌 | 有明确证券状态证据才豁免；无成交记录不自动视为停牌 |
| 财报 | 区分报告应披露、原件已找到、必要字段已提取且复核；预计日期与法定期限分开 |
| 历史可知性 | 先筛选截止点可用事实，再判断修订；今日补采不能修复过去 live_observed 缺口 |
| 重复/冲突 | 相同来源同键同值合并证据；不同值须显式修订；不同来源不静默平均 |
| 质量 | 身份、币种、价格口径、单位、期间、原件摘要和定位校验，异常保留核验 |
| 复查 | 采集成功不代表完整；返回完成、部分、待复核、阻塞或预期未知及剩余缺口 |

交易日历、停牌与披露预期是可追溯的输入事实，延迟容忍度是研究定义。缺少依据应报告未知，不能通过降低检测标准宣称完成。

## 工作包与验收门槛

1. 检测与补采：覆盖正常/半日/休市、未到期、缺日、财报待复核、历史不可补等场景；空响应仍报缺口，重复执行不重复登记，旧计划失效。
2. 真实来源：重新验证小米行情来源及字段口径；取得官方财报，保留原件和页码定位；登记来源限制，不把模拟样本冒充真实数据。
3. 数据整合：小米真实行情和至少一份真实财报经同一入库服务登记，能够查到结构化结果及对应原件；不实现预测或派生投资因子。
4. 应用入口：CLI 与 API 使用相同服务；网页能查看对象、记录、证据与缺口，并执行显式补采计划。API 固定工作区、限制操作与文件范围，默认本机监听。
5. AI 协作：更新并实操数据获取 Skill；MCP 若实现须用协议客户端握手与调用验收。CodeBuddy 无真实宿主时明确未验证，不以文件复制替代。
6. 工程验收：离线回归、真实小米执行记录、失败及恢复记录、页面实际访问、选择性 Git 提交与远端同步。

## 完成判定

最终逐项记录实现、离线验证、真实验收三种状态。任何来源、环境或原生宿主限制都保留为未完成项并给出具体解除条件；不得把该项改名为后续阶段以宣称全部完成。定时调度、公网服务部署以及指标预测复盘明确不在本轮范围。
