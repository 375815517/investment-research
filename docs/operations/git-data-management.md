# Git 数据管理约定

状态：2026-10-30 确立的目标合同。当前只有文档和空目录，发布器、同步任务、索引重建与校验器尚未实现。本文更新了此前将 Git 限于代码和方法的存储设计。

## 权威来源与目录

仓库共同保存代码、方法、原始资料、标准化数据及分析结果。完整的 Git 版本与其引用的 LFS 对象构成可恢复的研究档案。运行环境和凭据不属于研究档案。

| 目录 | 保存内容 |
| --- | --- |
| `data/inputs/companies/` | 企业档案、财报、经营数据与公告 |
| `data/inputs/industries/` | 行业分类、产业链、供需与行业报告 |
| `data/inputs/markets/` | 证券、行情、指数、公司行动与交易日历 |
| `data/inputs/macro/` | 经济指标、利率、汇率等宏观资料 |
| `data/inputs/policies/` | 政策、法律与监管原文 |
| `data/inputs/events/` | 公共事件、国际局势与事件进展 |
| `data/outputs/company-research/` | 企业研究正文、判断与证据 |
| `data/outputs/industry-research/` | 行业研究正文、判断与证据 |
| `data/outputs/market-research/` | 市场及跨领域专题研究 |
| `data/outputs/indicator-values/` | 指标、因子与语义评分的实际数值 |
| `data/outputs/predictions/` | 各期限预测及独立修订版本 |
| `data/outputs/evaluations/` | 到期评分、实验比较与评估依据 |
| `data/outputs/reviews/` | 复盘、偏差归因与改进建议 |
| `data/outputs/model-artifacts/` | 训练参数、权重与训练报告 |
| `data/outputs/research-records/` | 输入清单、执行状态、质量检查与模型响应证据 |

方法定义没有观测值；实际企业记录、指标数值、模型训练结果都进入数据层。研究产出再次作为输入时通过引用关联，保留其推断或产出身份。

## 业务归档与阅读方式

先按业务含义定位内容，再在对象目录中区分原件、整理后的数据和来源说明。一份政策归入 policies，多个企业和行业引用它；证券行情归入 markets，通过证券与企业关系关联公司。行业报告归入 industries，跨行业的宏观报告归入 macro。资料仅有一份权威归档，跨分类检索由元数据关系和派生索引支持。

下面仅展示拟定命名，未创建示例数据。revision_id 区分修订，正式文件不原地覆盖：

```text
data/inputs/companies/<company_id>/
├── profile/<revision_id>/profile.json
├── financials/<report_period>/<revision_id>/
│   ├── report.pdf               # 原件
│   ├── financials.json          # 整理后的数值，引用原件
│   └── source.json              # 来源、时间和摘要
└── announcements/<document_id>/<revision_id>/

data/outputs/company-research/<company_id>/<research_id>/<revision_id>/
├── report.md                    # 研究正文
├── evidence.json                # 证据引用
└── research.json                # 方法、运行及预测引用

data/outputs/research-records/<run_id>/
├── inputs.json                  # 本次使用的具体输入版本与摘要
├── run.json                     # 代码、方法、参数和执行记录
└── model-responses/             # 本次需要保留的 AI 响应
```

目录用于查找，记录中的稳定标识、时间和来源决定语义。国际事件可以同时关联地区、政策、产业和公司，不按所有关联对象重复存放。每次研究的输入清单属于研究记录，引用既有资料即可，不额外复制整个数据集。研究结果再次作为输入时同样引用其原始身份。

## 文件与版本合同

- 正文采用 Markdown；元数据及单条登记采用 JSON；批量记录按实际读取需求采用 JSONL、CSV 或 Parquet。具体 schema 后续定义，不在本次填充伪数据。
- 按数据集、对象、时间及批次分区。行情的建议形态为 `data/inputs/markets/prices/<security_id>/<period>/<batch_id>.jsonl`；正式研究产出使用 `<类别>/<对象>/<record_id>/<revision_id>/`。命名是后续实现约束，不表示当前已有数据集。
- 原件保存来源标识、原始 URL、公开时间、采集时间、报告期或事件时间、内容摘要及必要来源说明；不得把抓取时间当成公开时间。相同内容可共享原件，但各次采集的来源和时间单独记录。
- 标准化记录保留实体标识、单位、币种、适用时间、来源引用、转换方法版本及修订关系。行情同时明确价格和复权口径。缺失值不默认为零。
- 输入清单放在 `data/outputs/research-records/<run_id>/inputs.json`，固定输入文件、版本和摘要，承担快照职责；运行清单固定代码提交、方法版本、参数、输入快照与输出引用。涉及 AI 时保存实际模型标识、提示词版本、响应及证据；敏感凭据必须在持久化前剔除。
- 正式记录不原地修改。补数、纠错、失效、任务状态变化及预测修订采用新增记录并引用前版；最新视图由这些记录推导。历史预测继续按其原始信息截止时间评估。
- Git 提交哈希标识一次发布，但不能替代实体 ID、run_id、forecast_id 或业务时间。运行文件引用生成它的代码提交；发布提交由 Git 历史确定，不要求文件引用自己的提交哈希。

## 普通 Git、LFS 与缓存

优先用普通 Git 管理可审阅的文本和适量数据。大型 PDF、Parquet、模型权重可按路径用 `.gitattributes` 配置 Git LFS；目前没有启用 LFS，也不设置未经测量的统一文件阈值。

LFS 并不把大文件字节放进普通 Git 对象库。启用前应明确托管服务支持、单文件限制、容量、流量和备份方式；服务器和云环境都需要取得 LFS 对象。仅有指针不足以读取、分析或恢复数据。外部 URL 是来源信息，不能替代需要归档的原件。

SQLite、DuckDB、PostgreSQL、搜索和向量索引均为派生查询设施，可以从指定仓库版本重建。本机索引、数据库、下载暂存与未完成运行统一放在 `.research-local/`；禁止把正式预测、原始响应或不可重建证据只留在其中。数据文件不因“生成物”身份而被忽略。

## 发布与两端同步

目标流程：采集或研究 → 本地暂存 → 校验 → 形成完整运行包 → Git 提交 → 推送任务分支 → 整合到正式分支 → 服务器获取完整版本 → 切换展示并刷新派生索引。

1. 每次任务固定基准提交、输入快照和独立运行标识，使用单独分支或工作树；首次发布前检查文件格式、摘要、引用、时间口径、历史保护和密钥遗漏。
2. 关联资料与输出一起提交，失败的暂存包不发布。正式失败记录可以单独形成完整运行包并保存失败原因，不伪装为成功结果。LFS 对象需要上传成功才能作为可用版本交付。
3. 多端写入分工到数据集或任务路径，串行整合正式分支。相同采集批次使用稳定幂等标识；并发重复由校验拒绝或明确整合，不简单保留两份视为独立证据。
4. 出现非快进推送或同一对象版本分叉时，重新获取远端并检查语义冲突。文本能自动合并不代表研究记录可直接合并；禁止用强推、覆盖或丢弃未提交文件解决同步问题。
5. 展示服务器在独立检出目录获取指定提交，下载所需 LFS 数据、校验摘要并建立对应版本索引，成功后切换读取版本。展示版本与写入任务目录分开；失败继续展示上次有效版本并标记状态。
6. Git 同步只传递已提交内容，不自动触发采集或计算。后续部署流程显式负责更新与刷新；页面显示提交版本、数据截止时间和运行状态。

Git 提交是一次关联文件的版本边界，远端分支更新是多端整合边界；本地文件锁无法协调两个不同机器。后续发布实现、CI 与正式分支保护共同执行约束，不能依赖 Agent 自觉或 Hook 作为唯一保护。

## 恢复与容量演进

从干净目录恢复指定提交与全部必要 LFS 对象后，应能读取原件、解析快照、展示已保存的研究结果并重建索引。重新调用外部 AI 不要求得到相同响应，因此必须保存历史响应。采集新数据仍需来源访问和凭据，执行旧计算仍需对应依赖环境。

备份包含 Git 引用和历史，以及单独备份的 LFS 对象；远端仓库不是唯一备份。恢复演练检查摘要、证据引用和历史预测完整性。监测仓库增长、文件数量、克隆时间和 LFS 配额，优先通过合理分区、内容去重、选择性检出与批次发布控制增长。迁出权威数据或清理历史必须另作架构决策，不能默认由缓存清理承担。
