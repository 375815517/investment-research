# AI 协同投资研究工作空间架构

日期：2026-10-30。本文沉淀本次讨论已确定的目标、职责边界和目录组织。当前交付仅包含架构文档、根入口、目录骨架及旧内容暂存；文中的执行能力、接口、初始化工具和自动任务尚未实现。存储产品、框架与命令形式属于后续选型，不以目录存在表示已经可运行。

## 1. 长期目标

建立可长期持久化的投资研究项目，持续研究企业、行业和市场，记录公司披露、行业报告、政府信息、政策、公共事件、国际局势及对应证券和行业基准的行情。

以证据解释已发生的涨跌，积累指标、分析方法、因子与模型。基于当时可得信息形成下一交易日、下一周、下一月、一年、两年、三年六个期限的预测；保存原预测，到期评估实际结果，记录偏差与反思，用新的实验和观察改进数据、口径、模型及计算逻辑。

系统保证研究可追溯、方法可比较、历史可恢复。预测准确性和改进效果由真实评估证明，不承诺每次升级必然改善预测。既有项目不执行交易；交易执行、账户接入和收益承诺不属于本次确定的范围。

## 2. 三层架构

| 层 | 子部分 | 职责 |
| --- | --- | --- |
| 交互层 | AI 协作入口 | Codex、CodeBuddy 等宿主在仓库根目录理解目标、读取 Skills、组织研究和调用工具 |
| 交互层 | 可视化与应用接口 | 前端展示；CLI、API、可选 MCP 校验请求、查询数据、提交任务、返回结果 |
| 研究能力层 | 研究资产 | 提供规则、对象结构、定义、口径、Skills、因子、模型及流程；不保存实际观测数据 |
| 研究能力层 | 执行系统 | 将方法落实为采集、整理、语义分析、确定性计算、预测登记、评估和任务恢复 |
| 数据层 | 输入资料与数据 | 保存原始资料、标准化事实、行情、政策、事件和数据快照 |
| 数据层 | 研究与运行产出 | 保存分析、特征、模型制品、预测、评估、复盘和运行证据 |

依赖关系：交互入口调用统一应用能力；执行系统读取指定版本的研究资产及数据，生成并持久化产出；可视化查询同一结果。页面不另行实现指标、收益率、估值或评分逻辑。

研究产出可以成为后续研究的输入，但保留其身份、来源、时点和版本。AI 推断不能因为被多次引用就变成原始事实。复盘建议先作为产出保存，经验证后才成为研究资产的新版本。

## 3. AI 与确定性执行的分工

AI 负责理解资料、提取候选事实、识别关系、提出假设、寻找反证、组织研究、解释结果以及建议改进。Skills 提供这些活动的方法与输出约束。数学计算、单位换算、财务公式、数据筛选、预测登记和评分由程序按明确规则执行。

语义分析本身仍属于执行过程：可以由宿主 Agent 组织，也可以由后台任务调用模型接口；两者复用同一输入输出合同和登记能力。保存实际模型标识、方法版本、提示词、证据、工具调用和原始响应。外部模型的输出不假定能够逐字复现。

语义输出区分事实提取、分类、推断和条件情景。结构检查、证据引用检查及适用质量规则通过后，才供下游使用；缺失值与未知不默认为零。语义评分必须有定义、样例和评估依据，不能任意生成分数后加权为预测。

平台保证时点查询、版本检查、不可覆盖记录、幂等和计算约束。Markdown 规范与 Hook 指导 Agent，不能成为这些不变量的唯一保障。

## 5. 方法定义与执行实现

研究资产回答：采用什么方法，需要哪些输入，使用什么口径，产生什么输出，怎样验证。执行系统回答：本次实际使用哪个版本、什么输入、执行到哪里、结果如何、失败后怎样恢复。

指标定义声明公式、单位、适用期间、缺失值处理及实现引用；执行模块维护唯一计算实现，用测试保证与定义一致。Skill 和前端引用指标标识，不各写一套公式。

模型结构和训练策略属于研究资产；实际训练得到的权重、拟合参数和训练报告属于产出。模型注册记录绑定定义版本与训练制品。工作流定义属于 research-assets/workflows；调度、依赖执行和恢复机制属于 execution/orchestration。

每个运行固定方法版本、输入快照、参数和代码版本，保存 run_id、开始结束时间、执行状态、质量检查、输出引用和失败原因。重试使用幂等标识；发布使用事务和版本检查。采集失败不得覆盖最近有效数据，未知执行结果先查回再决定是否重试。

后台自动任务和交互式 Agent 共用能力接口。初期不自制完整自主 Agent；成熟流程由任务执行器运行，需要语义理解的步骤调用受控模型接口。是否引入自主规划层，以后续实际需要决定。

## 6. 输入数据与研究产出

输入涵盖企业与证券、行业和地区关系、财报与经营数据、股票与指数、公司行动、政府与宏观统计、政策原文、公共事件、国际局势、产业供需、行业报告和观点。观点、事实与研究者推断分别保留身份。

企业和证券分开建模，行业价格以明确的指数、ETF 或规则组合代理。实体关系和指数成分具有有效时间，避免用今天的成分重建过去。原始价格、分红及拆并股、复权版本、币种和交易日历分别保存。

每份数据区分事件时间或报告期、来源公开时间、实际采集时间、生效时间；保留修订关系、来源标识和内容摘要。数据集快照固定具体版本，后来的财报修订和行情补数不能改变旧预测的输入。

研究产出包含问题与范围、分析正文、判断与反证、指标及因子值、语义特征、训练制品、预测、评估、实验比较、复盘和执行证据。通过 snapshot_id、run_id、forecast_id 等稳定标识关联，不依赖聊天记录作为唯一记忆。

建议的存储职责是：Git 保存代码、定义和方法；关系数据库保存实体登记、版本引用、正式预测与评估状态；对象存储保存原件、Parquet、快照和运行包；分析引擎负责查询计算。PostgreSQL、S3 兼容存储、Parquet/DuckDB 是候选技术组合，尚未部署。

文件先写入、校验，再登记为可用；未完成制品不供下游读取。搜索索引和缓存可以重建，正式预测、原始模型响应及证据快照即使是生成物也必须长期保存。Git 忽略规则不能充当数据删除策略。

长期保存需要数据库与对象内容的一致备份、摘要校验和恢复演练。仅克隆 Git 或恢复云环境快照不代表完整研究历史已经恢复。

## 7. 预测、评估与方法演进

预测应保存对象、目标变量、发布时间、信息截止时间、输入快照、起始参考价格与口径、目标日期、方法版本、假设、反证及结果表达。修订产生新版本，旧版本照常评估。

六种期限在发布时固定为具体目标日期，并声明交易日历与非交易日处理。下一周采用交易日还是日历周、下一月采用交易日还是日历月，须由正式期限合同统一；本次不把尚未实现的约定描述为已有行为。

点预测、方向概率、统计区间和条件情景分别定义。未进行概率估计的情景不附造概率；未到期记录不填写最终结果。收益预测与可执行交易收益使用各自的起始价格和费用口径。

评估按目标使用点预测误差、概率校准、区间覆盖与宽度、因子排序关系及经营指标误差，并与明确基线比较。训练、调参、测试按时间隔离，处理重叠期限、未来信息、样本选择与多次试验偏差。失败实验也保留。

改进流程为：识别偏差 → 区分数据、口径、理解、公式和模型原因 → 提出变更 → 新实验比较 → 新样本观察 → 发布或放弃候选版本。评估可以推动新方法，但不能改写历史来制造成功。

## 8. 多宿主适配与初始化

维护一份共同规则与 Skills。根 AGENTS.md、CODEBUDDY.md 随 Git 提交，保持轻量，引用共同入口；宿主 Skill 副本、本机配置、回执、缓存和凭据不提交。必须提交的生成入口由模板生成并通过差异检查保持一致。单份维护指唯一权威来源，允许必要的兼容入口。

宿主 profile 声明规则入口、Skill 格式与发现路径、CLI/MCP 能力、Hook 事件、作用域、版本范围及验证方法。未知能力明确记录，不凭目录存在宣称支持；具体行为由工具实现，不执行任意 profile 脚本。

初始化工具采用 inspect、plan、apply、verify 的流程；升级复用同样机制。安装回执记录源版本、目标与摘要。重复相同安装返回 NOOP，冲突保留用户文件，修复和卸载仅处理可确认归属的内容。宿主原生信任与实际 Hook 触发分别核验。

预制 workspace-setup 和 workspace-maintenance 两个基础 Skill，分别指导首次设置和后续同步诊断。本次仅约定职责，尚未创建它们。首次引导必须在 README 提供无需已安装 Skill 的命令；原生发现、读取方法文件和实际执行能力分别报告。

下载即用分为三层：克隆后可理解项目并读已有正文；初始化后可执行完整离线示例；连接正式存储、来源及必要凭据后可接续真实研究。示例与正式运行复用实现和合同，demo 结果不进入正式预测成绩。当前骨架仅具备可阅读的架构入口。

## 9. 多 Agent 协作

宿主适配与并行协作分别设计。优先复用宿主原生委派，平台记录 task_id、work_unit_id、run_id、artifact_id 及结果整合记录。

独立检索和研究可以并行，但共同分析使用约定的截止时间与数据快照。每个执行者写独立草稿或产物；代码与方法按路径分工，同一文件串行集成。正式发布通过统一接口进行幂等和版本检查。

结果整合记录证据来源、意见分歧和采用理由。多个 Agent 引用同一来源不能算多份独立证据。接续从持久化任务与产物恢复，不以聊天摘要替代实际记录。

## 10. 可视化与应用接口

界面呈现数据新鲜度、企业和行业、市场与政策事件、证据关系、预测轨迹、到期评估、因子模型和实验比较。提供按历史时点查看的入口；任何数字都可以追溯来源和计算版本。

CLI、API 和可选 MCP 使用相同的应用服务。可视化后端负责校验、查询和任务入口，业务计算在 execution。界面更新时间与数据日期分开，过期或失败状态可见。图表不把相关性标成因果，不隐藏失败预测。

## 11. 演进顺序与验收

1. 建立根入口、宿主适配、数据和工具合同，用离线示例验证首次初始化及真实分析调用。
2. 建立采集、标准化、原件版本和时点快照，验证重放、失败保留、备份恢复。
3. 接通语义研究、确定性计算、预测发布与到期评估，验证完整证据链和历史保护。
4. 增加并行协作、自动任务、实验比较和可视化，依据实际瓶颈扩展来源与计算资源。

新增数据源检验字段、时间、修订与失败分支；新增指标检验口径与公式；新增 Skill 检验证据和正反例；新增因子模型检验泄漏与基线；新增工作流检验幂等与恢复。接口兼容和数据迁移另写设计决定，旧运行保留原版本解释能力。
