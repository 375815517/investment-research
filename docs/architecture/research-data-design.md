# 研究数据、知识与 AI 检索设计

日期：2026-10-30。状态：研究流程说明与人工可执行的 Skill 初版；输入结构已按 v1 封版。不是已实现的数据平台。输入目录、归属、字段与时间模式以 [输入数据结构基线 v1](input-data-baseline.md) 为准；本文补充研究语义与流程，不另定义存储路径。没有采集真实行情、配置实时订阅或启用自动发布。

## 1. 从价格时间轴组织研究

第一条基础链是证券身份 → 交易日历 → 原始价格与成交 → 公司行动 → 可比较的收益 → 预测目标与实际结果。日线起步，后续按需要扩展分钟或逐笔数据，不提前抓取全市场高频历史。

价格回答市场发生了什么，是预测评估的基础；财报、政策、经营、产业和竞争资料分别提供企业与环境发生了什么的证据。价格上涨本身不能证明某条新闻是原因。长期研究不能把原始财报视为价格的附注，也不能把媒体解释直接视为事实。

一次研究必须同时区分：实际发生的变化、变化前的预期、可检验的传导机制、市场反应，以及尚不能解释的部分。市场预期缺失时写缺失，不能用后来公布的结果重建‘此前大家都知道’。

## 2. 六种记录身份

| 记录 | 举例 | 如何使用 |
| --- | --- | --- |
| 来源原件 | 行情接口响应、交易所公告、政府文件、研报、帖子 | 保留原始字节或可保存的原文及出处；证明来源说过什么 |
| 可核实观测 | 某日收盘价、年报披露的收入、政策发布日 | 引用原件位置，记录口径、期间与修订 |
| 来源观点或预期 | 管理层指引、分析师预测、公众观点 | 标记作者、预测日期、样本与期限，不能当成已实现事实 |
| 实体关系 | 公司发行证券、行业归属、供应关系 | 带有效期间和证据；AI 猜测的关系留在研究产出 |
| 分析假设 | 补贴可能经销量影响利润 | 带传导链、条件、反证、后续检查，不写成已证实原因 |
| 验证与经验 | 后续销量符合假设，但利润未改善 | 保留原判断和检验数据；只有验证后的通用方法才进入 research |

AI 提取出的候选事实在核实前放入研究记录；核对原件、单位和期间后才登记为观测。模型自报的 confidence 不能充当真实性证明。

## 3. 对象与跨维度关系

企业、证券、行业、产品、政策、事件及资料使用稳定 ID。企业目录是唯一企业业务入口，不另设 subjects。每家公司首次建档由用户确认一只主证券；交易所、币种和代码有效期保存在证券档案，当前不单设 listings。企业本身与证券身份仍分开。

企业可以有多个业务板块，关系保留有效期与证据。竞争需限定产品、地区、客户群和时期；未经核实的供应或竞争关系留在研究假设。政策、行业信息单份共享，企业导航通过关系引用。

## 4. 输入归属与阅读入口

原件统一保存于 data/inputs/source-files，采集过程保存于 collection-records，业务目录仅保存整理后的记录。来源是获取渠道，不是研究对象；同一份年报可支持多个数据集，一次响应可支持多只证券。

正式路径、文件角色、小米示例和引用规则见 [输入数据结构基线 v1](input-data-baseline.md)。每批结构化数据附 batch.json；不在企业目录重复保存原件和行情。公司 README 聚合自身资料与共享信息链接，导航可重建，不能成为第二套事实来源。

## 5. 行情最小合同与质量

每条日线至少保存 security_id、交易场所、交易日期、时区、币种、open/high/low/close、volume、成交量单位、price_basis、session、来源及原件引用。amount、官方 previous_close、停牌状态在来源可提供时记录；缺失显式标记，区分停牌、休市、无成交、来源故障。OHLC 必须来自同一口径和交易时段。

供应商日线本身是汇总观测，不能称为逐笔交易原件。初期保存不复权价格作为基础观测。分红、拆并股、配股等公司行动独立保存公告、除权、生效与支付日期。供应商复权序列必须标记类型、锚点与版本，不能覆盖原始价；自行计算的复权价、收益和总回报属于 indicator-values，并绑定方法与公司行动版本。不同供应商的 close 或 volume 不默认可互换。

价格数据状态区分 accepted、provisional、quarantined，并保留原因；盘中未完成日线不能标记正式收盘。标准化主键包含证券、交易时段、日期、来源与版本；同一行情的多来源分歧记录并按来源选择规则使用，不静默取平均。校验：证券映射、OHLC 顺序、量额单位、日期唯一性、交易日覆盖、公司行动附近跳变、时间新鲜度和跨来源差异。异常涨跌先核查拆股与币种，不自动裁剪真实极端值。

当前选择小观察池的证券/年/批次分区。若扩展全市场，需评估文件数量并以迁移设计改为市场/年/批次，不能同时维护两套权威行情。历史导入按年分区；增量按明确采集批次写入，不每日重存全量历史。采集回执保存去敏请求参数，来源响应进入共享原件区，标准化批次引用原件及转换版本和摘要。周/月频由日线确定性聚合，声明交易日历和收盘取值规则。

预测与评估指定价格收益或含分红总回报、基准证券/指数、币种及费用是否计入。退市、停牌与并购结算不从成绩中删除；缺乏可评价终值时标记 pending/unavailable 并披露覆盖率。选择研究对象时保存当时的股票池，避免只研究今天仍存续的赢家。

## 6. 财务、预期、政策和舆论

财务记录保留期间、币种、数量级、会计准则、合并/单体、流量/时点、原始/重述版本和原件页码。累计值转单季值是计算结果，必须标记算法；不能把一季度累计同比与全年同比直接混用。

市场预期需要目标变量、对应期间、形成日期、作者或样本范围、汇总方法、分布和来源。公司指引与分析师一致预期分别保存。‘超预期’计算要求实际值与事先预期具有相同单位、期间和定义，找不到可核实预期时不生成 surprise 数值。

政策保存司法辖区、发布机构、适用对象、草案/通过/生效/废止阶段、文本版本及日期。行业数据注明覆盖范围、统计方法和修订批次。跨国宏观比较保留季调/非季调、实际/名义、同比/环比、年化方式；发布日期比统计期更决定当时是否可用。

舆论必须区分‘有此说法’与‘说法属实’。保存平台、作者、发布时间、抓取时间、原文/定位、样本获取方式；热度随时间变化独立记录。情绪评分必须声明样本范围和模型版本，不能由几条帖子推出全市场共识；广告、机器人和转载集中度属于质量标记。

## 7. 时间、当时可得性与实时性

至少区分 event_time/period、published_at、first_observed_at、ingested_at、valid_from/to、revision_id。时间包括时区与精度；只有日期时不能伪造精确分钟。回测只允许使用 cutoff 以前有可核实公开记录的版本；实际前瞻研究还要求系统在 cutoff 前已观察到该信息。历史补录单独标记，不能算成当时的实时发现。

运行清单声明 knowledge_mode：live_observed、historical_reconstruction 或 retrospective_explanation；事后解释允许后续资料，但必须标明其当时尚不可知，不能作为前瞻成绩。历史重建同时记录可得时间证据与缺口；今天首次取得的修订后财报不能代替当年的原版。输入清单固定文件版本和 SHA-256；每个数值和结论引用记录或原文位置。

‘实时影响’在初期表示按需更新的时点判断，不意味着已经提供实时行情。保存来源延迟、最后成功采集、数据截至时间、预期更新节奏、过期阈值和失败状态。收盘日线、盘中快照和新闻采样明确区分。交易时段、收盘后公布及不同市场休市按市场日历对齐。

## 8. 影响假设与后续核实

事件原件与影响判断分开。影响记录至少包括 hypothesis_id、event_id、目标对象、信息截止时间、传导机制、方向或条件情景、预期生效/持续区间、支持与反证、替代解释、待观察指标、复查日期和状态。方向允许 mixed/unknown；没有模型标定的主观判断不标精确概率。

例如某地区补贴：政策原文 → 公司业务在适用地区与产品的收入暴露 → 补贴是否传到消费者 → 订单/销量 → 折扣与毛利 → 现金流。订单增加并不保证利润增加。预先登记哪些观测支持/削弱每个环节，关注执行细则、预算、竞争降价及提前透支需求。

每个待核实任务保存 question、hypothesis_id、observable、preferred_sources、due_at 或 trigger、acceptance_rule、status、attempts、evidence_refs。状态包括 open、blocked、supported、contradicted、inconclusive、superseded。到期未有数据不等于假设被证伪；每次检查新增记录，保留失败检索和来源阻塞。结果、状态迁移由共享记录关联，不靠聊天提醒。

市场反应另外计算事件窗口收益、相对市场/行业基准收益、量能变化。明确估计窗口、事件窗口、并发事件、预期提前反映和样本限制；观察到超额收益只能支持关联，不能据此分配‘政策贡献 60%’等因果比例。盈利兑现与价格反应分别验证，允许‘业务改善但股价下跌’。

## 9. 给通用 Agent 的检索路线

1. 固定研究问题、对象、市场、期限、信息截止时间和知识模式；明确缺什么数据会阻止判断。
2. 解析企业/证券/行业标识与别名，读取版本化对象关系。不能仅按公司名称全文搜索。
3. 检查本地行情、公司行动、基准和数据覆盖；列出日期范围、缺失及口径，不先解释涨跌。
4. 沿企业 → 业务板块 → 行业/竞争/地区/政策/事件进行有界检索。每条扩展关系需有依据；优先补与当前问题相关的缺口。
5. 读取原件与精确证据位置，再提取候选事实；筛选 cutoff、来源层级、版本和可得性后才使用语义相似度排序。
6. 对缺口查第一方来源，再查可信二手资料。记录检索词、时间、来源、命中/未命中/阻塞和原件。检索摘要只用于定位，不作为已读原文证据。
7. 使用程序计算并留存参数与输出；AI 组织假设、传导机制、反证和竞争性解释。没有计算工具时写待计算，不能猜数。
8. 保存研究包、输入清单与后续核实任务，区分已证实、推断、冲突与未知。未经执行层校验的手工记录标记 draft/manual_review，不声称已经正式发布。

AI 检索入口需要两种小型目录：资料目录（ID、路径、对象、时间、类别、摘要、来源与质量）和研究目录（问题、结论、截止时间、输入、状态、待核实项）。权威信息保存在每份记录中；初期 Agent 用 rg 和文件读取按路径检索，后续索引在 .research-local 中重建。摘要和嵌入仅帮助定位，引用必须回到原件。

知识不是一份无限追加的总结。保留事实及版本、关系及证据、来源观点、原始假设、核实过程、失效结论及方法经验。企业概览可以生成，但需标记生成时间与引用；可变的概览不能替代历史研究包。

## 10. Skills 与分期验收

本次提供三个可由通用 Agent 显式读取的 Skill：[行情获取](../../ai/skills/market-data-acquisition/SKILL.md)、[证据检索](../../ai/skills/evidence-retrieval/SKILL.md)、[影响研究](../../ai/skills/impact-research/SKILL.md)。这三个领域指南与新增的通用数据流程 Skill 配合使用。首版 CLI 和宿主文件安装工具已实现，后台任务和原生宿主调用尚未验收；详见[运行手册](../operations/input-platform.md)。

实施顺序：

1. 一家企业的一只证券及市场/行业基准：验证身份、日线、日历、公司行动、单位、重采幂等、补数与断网失败；形成可核对的收益序列。
2. 接入一份财报、一条政策和一组行业数据：验证原件引用、时间、财务口径、对象关系与源数据修订。
3. 完成一次行情变化研究：冻结输入，保存竞争性解释与反证，生成明确的待核实任务；核实后追加结果。
4. 登记前瞻预测与基线，到期评分；加入服务器检索与定时刷新。随后再扩展更多企业、市场与高频数据。

跨市场比较还需固定汇率来源与换算时点；指数成分和权重保留历史版本。来源合同在 research/sources 中定义覆盖、更新、延迟、字段、访问和归档许可。资料不可合法归档时保留元数据与获取限制，明确证据不完整，不声称已恢复完整原件。

关键验收场景：拆股误报暴跌、同名异市场证券、收盘后新闻、后补重述财报、多个转载、无法打开的原文、无市场预期、未来才知道的行业成员、过期事件影响以及无终值的退市证券。每个场景都应产生明确缺口或正确版本，而不是让 AI 自动补全。
