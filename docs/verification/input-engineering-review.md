# 输入工程独立审查

日期：2026-10-30。审查角色：软件架构师、资深程序员；以当前工作区代码及临时目录复现实验为依据。此审查不代替金融来源真实性核验，也不把离线测试通过解释为上市以来全部资料已经取得。

## 结论

分层可继续演进：CLI/API/网页调用共享执行服务；领域类型是可执行合同；原件、采集回执、候选、复核、批次和研究记录分开；正式输入由 Git 保存，索引可以重建。当前适合小观察池的有界采集、复核入库及带限制的资料查询。未完成全市场规模性能验收、无人值守全渠道历史补采、多用户公网部署及原生宿主自动发现。

本次审查实际复现并修复三项工程问题，并交由应用实现者修复一项目录扩展问题。数据是否适用于具体分析，必须另看用途评估，不能根据框架完整或样本数量判定。

## 实际验证

- 独立运行 core、observations、market_status、market_status_time、expectation_time、ensure、API 合计 **85 项通过**；这是审查时的子集数量，最终全项目测试数量以最新验收记录为准。
- 发布检查 **7 项通过**，包含原有测试和新增参数用例。
- 本人修改的 Python 文件 Ruff 检查和格式检查通过；当时 mypy **23 个源文件通过**。
- 原件字节变动、批次文件摘要不符、manifest 与记录文件不一致由仓储读取拒绝；候选和复核摘要绑定、同源修订、重复窗口去重、中断恢复由上述既有测试覆盖。
- API 只提供本机服务；有 Host、同源写请求、显式客户端头、JSON 类型、文件路径/符号链接和正文大小约束。它不是具有登录、授权或租户隔离的公网服务。

测试不证明来源事实必然正确；excerpt 匹配证明原文有相应文字，不证明语义转换、比例分母或金融解释正确。reviewer 字段也不等于身份认证或独立审核。

## 后续扩展边界

1. **规模与性能**：`Repository.batches()`会读取全量批次并复核原件，`document()`会扫描原件元数据；多项需求核查重复执行这些操作。当前优先保证完整性，但扩展多企业多年资料前，应按不可变文件版本建立请求级快照或可重建索引，并保留摘要校验，避免为了速度取消证据检查。后续已实现audit/assess请求级只读快照：每次请求验证一次原件与批次、请求内复用，跨请求仍重验；32项真实需求约0.8秒。仍未进行全市场性能认证。
2. **公开时间修订**：同字节原件去重沿用首次登记元数据；后续采集回执保存新的 publication_assertion，但没有自动把它升级为历史查询的权威公开时间。需显式、可审查的元数据更正版本机制，不能手改旧 document.json。仅有公开日期的资料目前仍保守排除出严格时刻查询。
3. **覆盖与适用性**：audit-inputs 检查声明样本数，不是交易日历、完整报告序列或新闻总体的认证。资料全文入库、结构化字段完整、时间可用及可比较性是不同维度。新用途评估也须报告未评估范围，不能生成无依据的综合可信度分数。
4. **信任边界**：摘要检查防止文件与登记摘要不一致；Git 审查、显式发布清单和追加式历史共同保护正式记录。这不是抵抗具有仓库写权限者同时改原件及所有元数据的密码学认证系统。
5. **接入与宿主**：固定来源连接器和显式 Skill 调用已具备工程基础；来源网页变化、授权、限流、原生宿主发现、定时 worker/MCP/Hook 是独立验收事项。不能因为目录、模板或连接器名称存在就宣称完成。

本次范围仅输入平台及质量评估，不包括投资指标模型、预测、交易执行或收益保证。完整数据与金融口径限制见[小米多源验收](xiaomi-multi-source.md)及[金融审查](xiaomi-financial-data-review.md)。
